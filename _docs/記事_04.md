# 日本の祝日APIを作成してみた

## はじめに

内閣府が公開している祝日・休日のCSVを使って、JSONを取得できるサイトを作成しました。
サイト名は「内閣府『国民の祝日』JSON」、リポジトリ名は`cao-holidays-json`です。

カレンダーなどで祝日を表示するとき、日付をキーにして祝日の名称を取り出せると便利です。
そこで、内閣府のCSVを`2026-01-01`のような日付をキーにしたJSONへ変換し、全期間と年別のURLから取得できるようにしました。

この記事では、CSVの取得からJSONの生成、画面での表示、年次更新までの流れを解説します。
コードは[GitHubリポジトリ](https://github.com/tktkaws/cao-holidays-json)にまとめています。

### 技術スタック

- フレームワーク：Astro
- データの取得・整形：Node.js、csv-parse
- スタイリング：Tailwind CSS
- シンタックスハイライト：Astro標準のCodeコンポーネントに内蔵されたShiki
- フォント：IBM Plex Sans JP
- 定期実行：GitHub Actions

### 機能

- 全期間・年別の祝日JSONを取得
- 出典、取得日時、収録年、件数のメタデータを取得
- 年を選んでJSONの内容を確認
- JSONのシンタックスハイライト
- 内閣府のCSVを定期取得し、更新用のプルリクエストを作成

## 構成

### データを取得してから公開するまで

全体の処理は、次の順に進みます。

1. Node.jsのスクリプトで内閣府のCSVを取得する。
2. 文字コードを変換し、日付や名称を検証する。
3. 検証済みのデータをリポジトリ内のJSONに保存する。
4. Astroのビルドで、API用のJSONと表示用のHTMLを生成する。
5. 生成された`dist/`を静的ホストに公開する。

APIという名前ですが、公開時に配信するのはビルド済みのJSONファイルです。
アクセスのたびに内閣府のCSVを取得したり、データベースへ問い合わせたりする処理はありません。

データの取得とページの生成は別の処理にしています。
通常の`npm run build`では、すでに保存してあるデータからJSONとHTMLを生成します。

### ファイル構成

主なファイルは次のとおりです。

```text

```

### JSONの形式

祝日一覧は、日付をキー、名称を値にしたオブジェクトです。
次の例はレスポンスの一部です。

```json
{
  "2026-01-01": "元日",
  "2026-01-12": "成人の日",
  "2026-02-11": "建国記念の日"
}
```

全期間は`/api/v1/date.json`、指定した年は`/api/v1/2026/date.json`のようなURLで取得します。
メタデータは`/api/v1/metadata.json`で取得できます。

振替休日なども、内閣府のCSVに記載された名称を使います。
土曜日や日曜日をすべて含む一覧ではないため、日付が含まれていないことだけで営業日とは判断できません。

## 実装

### 内閣府のCSVを取得する

元データは、内閣府の[「国民の祝日」について](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)で公開されている[CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)です。

取得処理は`scripts/update-holidays.mjs`にまとめています。
次のコマンドで、CSVの取得から保存までを実行します。

```sh
npm run update:holidays
```

取得部分のコードは次のとおりです。

```js
export const source =
  'https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv';

const response = await fetch(source, {
  signal: AbortSignal.timeout(10000),
});

if (!response.ok) {
  throw new Error(`CSVの取得に失敗しました: HTTP ${response.status}`);
}

const holidays = parseHolidays(await response.arrayBuffer());
```

`AbortSignal.timeout(10000)`は、取得処理を10秒で打ち切るための指定です。
HTTPエラーの場合も処理を止め、取得できなかった内容を保存しないようにしています。

### Shift_JISのCSVを読み取る

CSVはShift_JISなので、まずバイト列として受け取り、`TextDecoder`で文字列へ変換します。

```js
import { parse } from 'csv-parse/sync';

const csv = new TextDecoder('shift_jis', {
  fatal: true,
}).decode(bytes);

const [header, ...rows] = parse(csv, {
  bom: true,
  skip_empty_lines: true,
});
```

`fatal: true`は、復号できないバイト列があったときにエラーにする指定です。
文字化けしたまま処理を続けることを防ぎます。

CSVの解析には`csv-parse`を使っています。
引用符で囲まれた値や、値の中に含まれるカンマもCSVの規則に従って扱うためです。

解析後は、ヘッダーが「国民の祝日・休日月日」「国民の祝日・休日名称」の2列であることを確認します。
さらに各行の列数、日付、名称、重複も検証します。

### 日付を整形して検証する

CSVの日付は、`2026/1/1`のような形式です。
月と日を2桁に揃え、JSONでは`2026-01-01`として扱います。

```js
const match = /^(\d{4})\/(\d{1,2})\/(\d{1,2})$/.exec(rawDate);

if (!match || !rawName.trim()) {
  throw new Error(`CSVの値が不正です: ${rawDate}`);
}

const [, y, m, d] = match;
const date = `${y}-${m.padStart(2, '0')}-${d.padStart(2, '0')}`;
const parsed = new Date(`${date}T00:00:00Z`);

if (
  Number.isNaN(parsed.getTime()) ||
  parsed.toISOString().slice(0, 10) !== date
) {
  throw new Error(`日付が不正です: ${rawDate}`);
}
```

正規表現だけでは、2月30日のような日付も形式上は通ってしまいます。
そこで、`Date`に変換した結果と元の日付を比較し、実在する日付かどうかも確認しています。

検証した値は`Map`に追加し、同じ日付がすでにあればエラーにします。
最後に日付の昇順で並べ替えて、JSONとして保存できるオブジェクトへ戻します。

```js
return Object.fromEntries(
  [...entries].sort(([a], [b]) => a.localeCompare(b)),
);
```

この形式なら、利用する側では`holidays['2026-01-01']`のように名称を取り出せます。

### 祝日とメタデータを保存する

保存先は`src/data/holidays.json`です。
祝日のオブジェクトに加え、出典、取得日時、収録年、件数を一緒に保存します。

以下は構造を示すサンプルで、祝日を2件だけにしたものです。

```json
{
  "metadata": {
    "source": "https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv",
    "fetchedAt": "2026-10-29T05:53:00.660Z",
    "years": ["2026", "2027"],
    "count": 2
  },
  "holidays": {
    "2026-01-01": "元日",
    "2027-01-01": "元日"
  }
}
```

`fetchedAt`はUTCの取得日時です。
これは内閣府がデータを更新した日時ではなく、このスクリプトがCSVを取得した日時を表します。
画面では日本時間に変換して表示します。

記事作成時の保存済みデータには、1955年から2027年までの1,067件が入っています。
収録範囲や件数は、今後のデータ更新によって変わります。

更新前のデータがある場合は、新しいデータとの差分も確認します。
追加・削除・名称変更をログに出力し、全件数が以前の90％未満になった場合や、以前収録していた年が消えた場合は保存を中止します。

保存時は、一時ファイルに書き込んでから保存先を置き換えます。
取得や検証が失敗した場合に、既存の保存データを残すための構成です。
差分の検査だけで内容の正確さを保証できるわけではないため、更新内容は公開前にも確認します。

### Astroで全期間のJSONを生成する

全期間のAPIは、`src/pages/api/v1/date.json.ts`で定義します。

```ts
import type { APIRoute } from 'astro';
import snapshot from '../../../data/holidays.json';

export const GET: APIRoute = () =>
  new Response(JSON.stringify(snapshot.holidays, null, 2), {
    headers: {
      'Content-Type': 'application/json; charset=utf-8',
    },
  });
```

Astroの静的構成では、この`GET`関数はビルド時に実行されます。
その結果、`dist/api/v1/date.json`というファイルが生成されます。
この仕組みは[Astroの静的ファイルエンドポイント](https://docs.astro.build/en/guides/endpoints/#static-file-endpoints)で説明されています。

返すのは`snapshot.holidays`だけなので、祝日一覧のレスポンスに`metadata`は含みません。
メタデータ用のエンドポイントでは、同じ保存ファイルの`snapshot.metadata`をJSONにして返します。

### 年別のJSONを生成する

年別APIのファイルは、`src/pages/api/v1/[year]/date.json.ts`です。
`getStaticPaths()`で収録年を列挙し、年ごとの生成先を決めます。

```ts
import type { APIRoute, GetStaticPaths } from 'astro';
import snapshot from '../../../../data/holidays.json';

export const getStaticPaths: GetStaticPaths = () =>
  snapshot.metadata.years.map(year => ({
    params: { year },
  }));

export const GET: APIRoute = ({ params }) => {
  const holidays = Object.fromEntries(
    Object.entries(snapshot.holidays).filter(([date]) =>
      date.startsWith(`${params.year}-`),
    ),
  );

  return new Response(JSON.stringify(holidays, null, 2), {
    headers: {
      'Content-Type': 'application/json; charset=utf-8',
    },
  });
};
```

`params.year`が、ファイル名の`[year]`に対応します。
2027年なら、日付が`2027-`で始まるデータだけを取り出してJSONにします。

未収録の年は`getStaticPaths()`に含まれないため、対応するファイルを生成しません。
そのURLにアクセスした場合の404表示は、公開先の静的ホストに従います。

### トップページに最新年を表示する

トップページの初期表示では、保存済みデータの最新年を使います。
現在の実装では、昇順に並んだ`metadata.years`の最後の値を取り出しています。

```ts
const years = snapshot.metadata.years;
const latestYear = years.at(-1)!;

const initialHolidays = Object.fromEntries(
  Object.entries(snapshot.holidays).filter(([date]) =>
    date.startsWith(`${latestYear}-`),
  ),
);
```

ここでいう最新年は、閲覧時の「今年」とは限りません。
記事作成時は2027年が収録済みなので、2027年の17件を初期表示します。
年の選択欄、API URL、表示件数も同じ年に揃えています。

API URLにはAstroの`BASE_URL`を使い、サブパスに配置する場合も考慮しています。
ブラウザーではリンクの`href`プロパティを表示文字列に使い、アクセス中のドメインを含むフルURLを表示します。

### ShikiでJSONを色分けする

JSONの表示には、Astro標準の`Code`コンポーネントを使っています。
内部でShikiを利用するため、Shiki用のインテグレーションを別に追加する必要はありません。

`src/components/HolidayJson.astro`では、祝日データを文字列に変換して渡します。
以下は、表示の中心となる部分を抜粋したものです。

```astro
---
import { Code } from 'astro:components';

interface Props {
  holidays: Record<string, string>;
}

const { holidays } = Astro.props;
---

<Code
  code={JSON.stringify(holidays, null, 2)}
  lang="json"
  theme="material-theme-lighter"
  wrap={null}
/>
```

テーマはMaterial Theme Lighterを指定しています。
実際のコンポーネントには、Tailwindのクラスで高さの上限やスクロール、余白も設定しています。

`Code`コンポーネントはビルド時にHTMLを生成します。
ブラウザーへShiki本体を配信せず、初期表示のJSONを色分けできます。
対応するプロパティは[Astroのシンタックスハイライトの説明](https://docs.astro.build/en/guides/syntax-highlighting/#code)で確認できます。

### 年を切り替えたときもハイライトする

年を選び直した場合も、ビルド済みのハイライトを利用します。
そのために、`src/pages/json-preview/[period].astro`で全期間と年別のHTMLを生成しています。

```astro
---
import type { GetStaticPaths } from 'astro';
import HolidayJson from '../../components/HolidayJson.astro';
import snapshot from '../../data/holidays.json';

export const partial = true;

export const getStaticPaths = (() => [
  {
    params: { period: 'all' },
    props: { holidays: snapshot.holidays },
  },
  ...snapshot.metadata.years.map(year => ({
    params: { period: year },
    props: {
      holidays: Object.fromEntries(
        Object.entries(snapshot.holidays).filter(([date]) =>
          date.startsWith(`${year}-`),
        ),
      ),
    },
  })),
]) satisfies GetStaticPaths;

const { holidays } = Astro.props;
---

<HolidayJson holidays={holidays} />
```

`partial = true`は、ページ全体ではなくHTMLの断片を生成する指定です。
`/json-preview/2027/`には、2027年のJSONをハイライトしたコードブロックが入ります。
HTMLの断片については[Astroのページパーシャル](https://docs.astro.build/en/basics/astro-pages/#page-partials)を参考にしました。

ブラウザーで年を切り替えたときは、次の順に表示を更新します。

1. 選んだ年のAPIからJSONを取得する。
2. JSONを整形し、テキストとして表示する。
3. 同じ年のハイライト済みHTMLを取得する。
4. HTML内のコード内容が取得したJSONと一致したら差し替える。

キャッシュなどの影響でJSONと表示用HTMLの内容が異なる場合は、APIから取得したJSONをそのまま表示します。
表示用HTMLを取得できない場合も、色分けなしで内容を読めます。

また、年を続けて変更するとリクエストの応答順が入れ替わることがあります。
実装ではリクエストに連番を付け、現在の選択に対応しない古い応答を表示へ反映しないようにしています。

### Tailwindと日本語フォントを設定する

スタイルはTailwindのユーティリティクラスで指定しています。
背景は白、基本文字色は黒とし、操作部分には淡いグレーのパネルを使いました。

フォントはFontsourceからIBM Plex Sans JPを導入しています。
`src/styles/global.css`では、使う太さを読み込み、Tailwindの`font-sans`へ登録します。

```css
@import "tailwindcss";
@import "@fontsource/ibm-plex-sans-jp/400.css";
@import "@fontsource/ibm-plex-sans-jp/500.css";
@import "@fontsource/ibm-plex-sans-jp/600.css";
@import "@fontsource/ibm-plex-sans-jp/700.css";

@theme {
  --font-sans: "IBM Plex Sans JP", ui-sans-serif, system-ui, sans-serif;
}
```

本文や見出しにはこのフォントを使い、API URLとJSONには`font-mono`を指定しています。
フォントファイルもビルド成果物に含め、サイトから配信する構成です。

## GitHub Actionsで年次更新する

### 定期実行の設定

更新のワークフローは、`.github/workflows/update-holidays.yml`に置いています。
毎年10月29日16時、日本時間で実行する設定です。

次のコードは、実行タイミングの設定を抜粋したものです。

```yaml
on:
  schedule:
    - cron: '0 16 29 10 *'
      timezone: Asia/Tokyo
  workflow_dispatch:
    inputs:
      dry_run:
        description: 'テスト実行（PRを作成・更新しない）'
        type: boolean
        default: true
```

`cron`で日時を指定し、`timezone`で日本時間を指定しています。
GitHub Actionsのスケジュール実行はデフォルトブランチが対象です。
設定方法は[GitHub Actionsのscheduleの説明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)で確認できます。

この日時は、このプロジェクトで決めた取得スケジュールです。
内閣府が必ずこの日にCSVを更新する、という意味ではありません。

### 検証後に更新用のプルリクエストを作成する

定期実行では、次の処理を順番に行います。

1. `npm ci`で依存パッケージをインストールする。
2. `npm run update:holidays`でCSVを取得・保存する。
3. `npm test`でテストを実行する。
4. `npm run build`でJSONとHTMLを生成する。
5. `check-holiday-build.mjs`で翌年のデータと生成結果を確認する。
6. 成功した場合に、更新用のプルリクエストを作成・更新する。

更新ブランチ名は`automation/update-holidays`です。
既存の更新プルリクエストがあれば、同じブランチを更新します。
いずれかの検証で失敗した場合は、プルリクエストの作成まで進みません。

`check-holiday-build.mjs`では、日本時間の実行年から翌年を求め、保存データに収録されていることを確認します。
あわせて、全期間・メタデータ・翌年分の生成JSONが、保存済みデータから期待される内容と一致するかを確認しています。

祝日の内容が変わっていなくても、CSVを取得した日時は更新されます。
そのため、取得日時だけが変わるプルリクエストになる場合もあります。

このワークフローには、自動マージや公開先へのデプロイは含めていません。
更新内容を確認してマージし、ビルド成果物を公開した段階で、利用者が取得するAPIに反映されます。

### 手動で確認する

`workflow_dispatch`も設定しているので、GitHubのActions画面から手動実行できます。
初期状態では「テスト実行（PRを作成・更新しない）」が有効です。

この状態でもCSVの取得、テスト、ビルド、生成結果の確認まで実行します。
プルリクエストも作りたい場合は、チェックを外して実行します。

ワークフローを使うには、デフォルトブランチへの反映と、GitHub Actionsによるプルリクエストの作成許可が必要です。
スケジュール実行は遅延することもあるため、Actionsの履歴と更新プルリクエストの状態を確認します。

## ローカルでの確認と公開

### ローカルで動かす

リポジトリを取得したら、Node.js 22.23.4以降の環境で依存パッケージをインストールします。

```sh
git clone https://github.com/tktkaws/cao-holidays-json.git
cd cao-holidays-json
npm install
npm run dev -- --background
```

保存済みデータが含まれているため、画面を確認するだけならCSVを取得し直す必要はありません。
開発サーバーは次のコマンドで管理します。

```sh
npm run astro -- dev status
npm run astro -- dev logs
npm run astro -- dev stop
```

CSVを更新した内容を確認するときは、取得後にテストとビルドを実行します。

```sh
npm run update:holidays
npm test
npm run build
node scripts/check-holiday-build.mjs
```

最後の確認コマンドは翌年の収録を前提にしています。
内閣府のCSVに翌年分がまだ含まれていない時期は、この確認で失敗する場合があります。

### 静的ホストへ公開する

Astroのビルド結果は`dist/`に出力されます。
このディレクトリを静的ホストに配置すれば、トップページ、API用のJSON、ハイライト済みHTMLをまとめて配信できます。

リポジトリには特定の公開先へデプロイする設定を含めていないため、公開先の設定は別途行います。
ビルドコマンドは`npm run build`、公開するディレクトリは`dist`です。
サブパスに配置する場合は、Astroの`base`も配置先に合わせて設定します。

公開後は、全期間・年別・メタデータのURLに加え、未収録年の404と、画面での年の切り替えも確認します。
更新後の内容が配信されているか、取得日時やキャッシュも確認します。

別サイトのブラウザーから`fetch`で利用する場合は、公開ホストのCORS設定が必要になる場合があります。
このリポジトリのエンドポイントにはCORSヘッダーを設定していないため、同じサイト内で取得できることと、別のドメインから利用できることは分けて確認します。

## おわりに

Astroを使って、内閣府のCSVを日付と名称のJSONとして配信するサイトを作成しました。

CSVの取得と検証をNode.jsのスクリプトにまとめ、Astroでは保存済みデータからJSONとHTMLを生成しています。
画面のJSON表示にもビルド時のShikiを使い、年の切り替え時には生成済みのHTMLを読み込むようにしました。

祝日データは年をまたいで更新が必要になるので、GitHub Actionsで定期取得と更新候補の作成まで行います。
更新内容の確認と公開を別の工程にすることで、変更されたデータを確認してからAPIへ反映できる構成にしています。
